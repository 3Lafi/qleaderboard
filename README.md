# وسام

تطبيق عربي لمتابعة حفظ القرآن: لوحات المعلم، الدفعات، جدول تسجيل الحفظ، ملفات الطلاب، والأوسمة.

## التشغيل والتحقق

```sh
npm ci
npm run dev
npm run verify
```

افتح `http://localhost:8080`. يتحقق `verify` من اعتماديات الطبقات، الوحدات غير المستخدمة، الملفات والموارد المشار إليها، وصحة JavaScript، ثم يشغّل اختبارات المجال والتنقل.

لا يحتاج التطبيق إلى خطوة تجميع؛ يستعمل وحدات JavaScript الأصلية. إعدادات مشروع Firebase العامة موجودة في `js/data/firebase/firebase.js`، وقواعد الوصول في `firestore.rules`.

## هيكل التطبيق

- `js/domain`: نماذج وقواعد الحفظ والترتيب والأوسمة؛ بلا Firebase أو DOM.
- `js/application`: سياسة المسارات وإدارة دورة حياة زيارة الصفحة.
- `js/shared`: بيانات القرآن والمناهج والنصوص والإعدادات المشتركة؛ بلا اعتماد على بقية الطبقات.
- `js/data`: محولات Firebase والمصادقة ومستودعات اللوحات والدفعات.
- `js/presentation`: الصفحات، المكونات، الهيكل العام، وربط History API بالمتصفح. تستقبل الصفحات المستودعات وحالة المستخدم بدلاً من استيراد Firebase.
- `js/app.js`: نقطة تركيب الاعتماديات وتشغيل التطبيق.
- `css/tokens.css`: المصدر الموحد للألوان والمسافات الثابتة ومتغيرات التصميم. ملفات CSS الأخرى تستهلك هذه المتغيرات.

## المسارات

| المسار | الصفحة | الوصول |
|---|---|---|
| `/` | الرئيسية | الجميع |
| `/badges?level=quran` | مكتبة الأوسمة؛ `quran` أو `juz` أو `surah`، والبحث `q` | الجميع |
| `/login?next=…` | تسجيل الدخول والعودة للوجهة المطلوبة | الزائر |
| `/dashboard` | لوحاتي | المعلم |
| `/cohorts`، `/cohorts/:id` | الدفعات وتفاصيل الدفعة | المعلم المالك |
| `/new` | إنشاء لوحة | المعلم |
| `/edit/:id` | إعدادات اللوحة | المالك |
| `/edit/:id/students` | جدول المتابعة | المالك |
| `/edit/:id/students/:studentId` | ملف الطالب داخل مساحة المعلم، بما فيها اللوحات الخاصة | المالك |
| `/b/:id`، `/b/:id/students/:studentId` | اللوحة العامة وملف الطالب المنشور | اللوحة المنشورة فقط |

المسارات غير المعروفة تعرض صفحة استعادة داخل تصميم التطبيق. الروابط القديمة بصيغة `#/…` تتحول إلى مسارات عادية. عناوين `almanhaj` و`juz_amma` و`juz_tabarak` القديمة، مع `.html` أو بدونها، تتحول إلى الرئيسية؛ لم يعد تطبيق Google Sheets القديم جزءاً من المشروع.

## الاختبار دون بيانات حقيقية

افتح `http://localhost:8080/tests/ui/preview.html?page=dashboard`. تستخدم المعاينة **نفس الموجّه والصفحات** مع مستودعات ومصادقة في الذاكرة؛ لا تستورد Firebase ولا تصل إلى بيانات الطلاب الحقيقية. مسارات المعاينة تحت `/tests/ui/app/` تدعم الرجوع والتقدم وإعادة التحميل. بياناتها تعود للقيم الأصلية عند إعادة التحميل.

خيارات مفيدة: `page=students`، `page=cohort`، `page=new`، `privateBoard=1`، `guest=1`، `loadDelay=1000`، `saveDelay=1000`، `tools=1` لإظهار أدوات محاكاة فشل الحفظ. ملفات `tests/ui/*.mjs` الأقدم هي أدوات فحص بصري يدوية وليست جزءاً من `verify`؛ دليل التنقل الجديد ومراجع التصميم في `docs/sidebar-navigation.md`، ونتائج المراجعة في `docs/audit/navigation-redesign/review.md`.

لاختبار قواعد الوصول يلزم Java وFirebase CLI:

```sh
npm run test:rules
```

تستخدم هذه الاختبارات مشروع محاكاة محلياً، ولا تكتب في مشروع الإنتاج. يستبعد إعداد Hosting الاختبارات والمستندات والبرامج المساعدة والسجلات من النشر.

## أصول التصميم

الأيقونة ووسام القرآن يستخدمان الزخرفة النباتية المحسّنة v10 مع الحفاظ على الخط والإطار الأصليين. راجع `docs/badge-design.md` لإعادة توليد الأصول، و`docs/badge-comparison.html` للمقارنة البصرية.
