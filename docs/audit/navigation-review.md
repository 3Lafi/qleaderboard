# Routing, architecture and design review — 12 September 2026

The app now has one route policy, one browser router and one persistent shell. Firebase services are injected at the composition root. The public board, owner workspace, student profiles, cohorts, authentication and recovery screens use the same design tokens and navigation model.

## Findings repaired

1. **A slow page could overwrite a newer page.** The previous router passed every renderer the same container and checked its navigation token only after rendering completed. Each visit now owns a separate host, abort signal, guarded presentation callbacks and subscription cleanup. Regression tests resolve a slow page after navigating away and verify the current content, title, layout and URL remain intact.
2. **Closing the mobile drawer created phantom Back steps.** Opening pushed a history entry; closing did not remove it, and an open drawer could consume a real route pop. The drawer now stays out of history. Back/Forward uses the actual route and closes the drawer. Verified table → profile → drawer open/close → Back → table → Forward → profile.
3. **Private board links led to public/unavailable pages.** Board rows and the picker now open the owner's worksheet. Owners have `/edit/:boardId/students/:studentId`; public URLs retain their visibility checks. Missing boards clear the unusable context links. [Private table](screenshots/02-private-students.png), [private profile](screenshots/03-private-profile.png), [missing-board recovery](screenshots/mobile-missing-board.png).
4. **Sign-out left protected content mounted; sidebar results could outlive an account.** Auth changes now reroute the active page and clear board/student context immediately. Stale board-list responses cannot repopulate another account. Verified sign-out from a private student profile, then sign-in returning to that profile. [Sign-in recovery](screenshots/04-signout-login.png).
5. **Collection cards opened the wrong badge level.** Home cards link to `?level=quran|juz|surah`; collection and search state are restored from the URL. Verified the real homepage's Quran link and reload retention. [Quran collection](screenshots/final-quran-collection.png).
6. **The mobile setup action bar overlapped the bottom navigation.** Both bars now share a height token and safe-area spacing. Retested all three setup steps at 390px width; creation reached the correct student table. [Setup before the spacing fix](screenshots/mobile-new.png), [corrected actions](screenshots/mobile-setup-actions-fixed.png), [created board](screenshots/mobile-created-board.png).
7. **The worksheet called a missing `recorder.toggle` method.** Added and tested the use-case operation. A real fixture click now saves, updates sidebar progress, and appears in the student profile. Queued persistence can finish after navigation while stale presentation callbacks stay cancelled. [Profile after saving](screenshots/mobile-profile-saved.png).
8. **Progress maps rounded small accomplishments to zero.** The model retains the precise percentage and the shared formatter displays 0.24% for the first three short surahs. [Public profile](screenshots/final-public-profile.png).
9. **Recovery and secondary pages drifted from the shared UI.** Consolidated global design variables in `css/tokens.css`, removed nested `main` landmarks, unified loading/recovery icons, and corrected duplicate top-level headings in dashboard empty/error states. Reviewed dashboard, cohort list/detail, setup, settings, public boards/profiles and sign-in. [Dashboard](screenshots/desktop-dashboard.png), [cohort list](screenshots/desktop-cohorts.png), [cohort detail](screenshots/desktop-cohort.png), [settings](screenshots/desktop-settings.png), [public board](screenshots/final-public-board.png), [404](screenshots/mobile-not-found.png).
10. **Retired implementations and artwork remained in the runtime tree.** Removed the old Google Sheets app, duplicate router/header/breadcrumb components, unmounted views and their CSS, unused exports, and rejected/obsolete artwork. The asset/helper cleanup removed approximately 62.2 MiB. The original badge reference, active artwork, calligraphy and rebuild sources remain. Old HTML bookmarks redirect to the homepage. Exact removals are recorded in [removed-code.txt](removed-code.txt).

## Validation

- `npm run verify`: **109 tests passed**, plus checks on **57 runtime modules** for syntax, import resolution, permitted layer dependencies, reachability, and referenced static resources.
- HTTP checks: **12 SPA deep links**, **3 legacy redirects**, and **5 essential static resources** passed against the local server.
- In-app browser: teacher dashboard, cohorts and cohort detail, all setup/settings steps, privacy changes, new-board → add-student → save → profile, private/public student routes, sign-out and return destination, drawer/Back/Forward, badge selection/reload, dialog cleanup, 404 and missing-board recovery. Narrow phone (390px), desktop (1280px) and the normal browser viewport were inspected.
- The final checked flows produced no browser runtime errors. Earlier failures found during the review were fixed and retested.
- Firestore emulator rules were **not executed**: the emulator cannot start because Java is absent on this host. No rules or live student records were changed. A machine with Java and Firebase CLI can run `npm run test:rules`.
- Teacher-flow browser checks used isolated in-memory adapters with the actual router and pages. Real Google sign-in, live Firebase CRUD, and production deployment were not exercised. The production-facing landing page and badge library were checked locally.

## Repeatable browser checks

Start `npm run dev` and use `/tests/ui/preview.html?page=dashboard`. This fixture does not load Firebase. Add `tools=1` to expose the save-failure toggle, `privateBoard=1` for private-board flows, or `loadDelay=1000`/`saveDelay=1000` for slow requests. Reload resets fixture data.

For any navigation change, repeat: dashboard → worksheet → owner profile → Back/Forward; drawer open/close and backdrop/Escape; sign-out from a protected route and sign-in return; setup at phone width; toggle/retry a worksheet cell; private/public/missing records; badge level/search and reload; static documents/downloads; rapid navigation while a page is loading. Use the same production router rather than a separate mock route map.
